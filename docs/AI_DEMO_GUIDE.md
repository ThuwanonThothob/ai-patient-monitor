# คู่มือเดโม: ให้เห็นการทำงานของ AI อย่างตรวจสอบได้

อัปเดต 3 ตุลาคม 2026 — งานวิจัย/สาธิต ไม่ใช่อุปกรณ์แพทย์ที่ผ่านการรับรอง

## สิ่งที่เพิ่มในรอบนี้

1. **AI และประวัติระบบ → Scenario Test Center**: กดทดสอบปกติ, SpO₂ ต่ำ, เซนเซอร์หลุด และอยู่ท่าเดิมนาน แล้วเห็น Data → Quality → Model → Decision → Action → Ground Truth ในหน้าเดียว
2. **พิสูจน์ AI → พยากรณ์สัญญาณชีพ**: เลือกไฟล์ BIDMC ชุดทดสอบ หยุดข้อมูลที่จุดหนึ่ง แล้วดูผลพยากรณ์ +30 วินาทีก่อนเปิดผลจริง พร้อม baseline และความคลาดเคลื่อน
3. **พิสูจน์ AI → จำแนกท่าบนเตียง**: ใช้ข้อมูลแผ่นแรงกดจริงจาก PMD เทรน classifier เปรียบเทียบสองโมเดล แสดง heatmap คะแนนโมเดล เฉลย และเคสที่ผิด/งดตอบ
4. **แผนดูแล**: ร่างแผนราย ID → คนตรวจยืนยัน → งานถึงกำหนด → รับงาน → บันทึกผล/ข้ามพร้อมเหตุผล มีประวัติและรายงาน Text

ทั้งสามส่วนอยู่ในพอร์ตบุคลากรเท่านั้น ไม่เพิ่มการเรียก Gemini อัตโนมัติ ไม่ส่ง Push จากข้อมูลวิจัย ไม่ติดต่อแพทย์หรือรถพยาบาลจริง ไม่แก้ข้อมูล `.env` หรือเวชระเบียนเดิม

## รันบนเครื่องเดิม

จากโฟลเดอร์โปรเจ็กต์:

```bash
source .venv/bin/activate
python3 scripts/run_ward.py --check
python3 scripts/run_ward.py
```

ถ้า launcher เดิมยังทำงานและต้องการโหลดโค้ดใหม่ ใช้ `python3 scripts/run_ward.py --restart`
หากเปิด Uvicorn/Next แยกเอง ให้หยุดและเริ่มเฉพาะ terminal ของโปรเจ็กต์เดิม ไม่ฆ่า process ที่ไม่ทราบเจ้าของ

- บุคลากร: `http://localhost:3000/?section=evidence`
- แผนดูแล: `http://localhost:3000/?section=care`
- ผู้ป่วย: `http://localhost:3001/` (ไม่แสดงหน้าวิจัย/แผนบุคลากร)
- รหัสบุคลากรยังเป็นรหัสเดิมจาก `WARD_STAFF_PASSWORD` หรือ `backend/.staff-password` ไม่ใช่รหัสทดสอบของผู้พัฒนา

โมเดล PMD เทรนและเก็บไว้ในเครื่องนี้แล้ว ถ้า clone ไปเครื่องใหม่ต้องดาวน์โหลดและเทรนแยก (launcher ยังเตรียมอัตโนมัติเฉพาะ BIDMC):

```bash
cd backend
python3 -m ml_pipeline.download_pmd
python3 -m ml_pipeline.train_posture
```

ใช้ dependencies ML เดิม ไม่ต้องมี Gemini key ไม่ต้องติดตั้ง CrewAI และไม่ต้องมี GPU
ไฟล์ข้อมูล/โมเดลไม่ commit เข้า Git; downloader ตรวจ SHA-256 ของเจ้าของข้อมูลและข้ามไฟล์ที่ตรวจผ่านแล้ว
อย่าเทรนหลาย process พร้อมกัน และอย่าโหลด `.joblib` จากบุคคลที่ไม่น่าเชื่อถือ

## เดโมให้อาจารย์ภายใน 5–7 นาที

### 0. แสดงเส้นทางทีม Agent ก่อน (ประมาณ 1 นาที)

1. เข้าพอร์ตบุคลากร → **AI → AI และประวัติระบบ**
2. เลือก Scenario “SpO₂ ลดต่อเนื่อง” แล้วกด **รัน Scenario แบบไม่ส่งจริง**
3. อ่านหกขั้นตามลำดับ: ข้อมูลเข้า → Quality Gate → Dataset/Model → Agent Decision → การกระทำ → Ground Truth
4. แสดงว่าระบบตอบว่า “Workflow ตรงตามที่คาด” และ action ระบุ `live_side_effects=false`
5. ลอง “เซนเซอร์หลุด” เพื่อแสดงว่า Data Quality หยุดโมเดลและ Device Health เสนอให้ตรวจอุปกรณ์ ไม่ตีความค่า 0 ว่าผู้ป่วยวิกฤต

Scenario ทั้งสี่เป็น controlled fixture เพื่อทดสอบ software routing เท่านั้น เก็บในตาราง
`agent_scenario_runs` แยกจาก vital, alert และ Ground Truth จริง ไม่ส่ง Push และไม่นำไปฝึกโมเดล
จากนั้นกด **เปิดหลักฐานโมเดลจริง** เพื่อแยกการทดสอบ workflow ออกจากการประเมินโมเดลบน BIDMC/PMD

### 1. แสดงการพยากรณ์ก่อนเห็นอนาคต (ประมาณ 2 นาที)

1. เข้าสู่พอร์ตบุคลากร → **พิสูจน์ AI → 01 พยากรณ์สัญญาณชีพ**
2. เลือกไฟล์ชุดทดสอบ จุดเริ่มต้น 59 วินาที ทำให้มีอดีตครบ 60 จุด
3. อธิบายว่า input คือ HR, SpO₂, RR จริงจาก BIDMC ไม่ใช่โรค/น้ำตาล/ECG ที่สร้างไว้ในทะเบียนสาธิต
4. แสดงผลพยากรณ์ที่ +30 วินาที ตอนนี้ช่องค่าจริงยังว่าง เพราะยังไม่เปิดอนาคต
5. กดเล่นย้อนหลัง 1 วินาที/จุด หรือปุ่มเปิดผล +30 วินาที จากนั้นเปรียบเทียบค่าจริง ความคลาดเคลื่อนโมเดล และ baseline ที่ใช้ค่าล่าสุดคงเดิม
6. เปิด input features 21 ค่า และตารางผลทั้ง 778 หน้าต่างชุดทดสอบ ไม่สรุปความแม่นยำจากเคสเดียว
7. ลากจุดเริ่มต้นกลับไปต่ำกว่า 59 เพื่อแสดง **ABSTAIN** เมื่อข้อมูลไม่พอ
8. ดาวน์โหลด Text ณ จุดที่เปิดอยู่ รายงานจะไม่ใส่ผลจริงจากอนาคตที่ยังไม่ได้เปิด

พยากรณ์ถูกตรึงที่จุดตัด ไม่เปลี่ยนเมื่อเปิดผลจริง ความผิดพลาดเป็น absolute error ตามหน่วยเดิม ไม่ใช่ “ความแม่นยำเป็นเปอร์เซ็นต์” เส้นประเชื่อมถึงจุด +30 ไม่ได้หมายความว่าโมเดลพยากรณ์ทุกวินาที

**ข้อเท็จจริงที่ต้องบอก:** Random Forest HR/RR ในผล test ปัจจุบันยังไม่ชนะ persistence baseline (ดู README) และ Isolation Forest ไม่มี label โรค จึงไม่รายงาน disease accuracy

### 2. แสดง classifier ที่เทรนจากแผ่นแรงกด (ประมาณ 2 นาที)

1. เปิด **02 จำแนกท่าบนเตียง** ดู heatmap จากเซนเซอร์ 32×64 จุด
2. โมเดลอ่านรูปแบบแรงกดผ่าน 128 features แล้วจำแนก นอนหงาย/ตะแคงซ้าย/ตะแคงขวา ไม่ใช้ชื่อไฟล์หรือ label เป็น input
3. อ่านคำทำนายก่อนกด “เปิดเฉลยจากผู้เก็บ Dataset” (API ซ่อนชื่อไฟล์และเลขท่าที่อาจเปิดเผยเฉลยด้วย)
4. ดูตัวกรองเคสผิดและงดตอบด้วย อย่าแสดงแต่เคสถูก ตัวกรองนี้ใช้เฉลยย้อนหลัง จึงไม่ใช่ blind evaluation
5. แสดง confusion matrix, train/validation/test ที่แยกคน และดาวน์โหลดรายงาน

### 3. ปิดงานดูแลโดยคน (ประมาณ 1 นาที)

1. เปิด **แผนดูแล** เลือก Patient ID ในทะเบียนสาธิต
2. สร้างงาน “ตรวจอุปกรณ์วัดสาธิต” พร้อมรายละเอียด ผู้รับผิดชอบ เริ่ม 0 นาที ทำครั้งเดียว
3. แผนยังเป็น DRAFT และไม่สร้างงานจนกว่าจะติ๊กตรวจแผนแล้วกดเปิดใช้
4. รับงาน → กรอกผล → บันทึกว่าเสร็จแล้ว ดูประวัติและดาวน์โหลด Text
5. แสดงว่าอีก Patient ID ไม่มีงานนี้

ส่วนนี้คือ **rule-based workflow ไม่ใช่ ML** ไม่มีความถี่พลิกตัวหรือคำสั่งรักษาที่ AI กำหนดเอง ชื่อผู้รับผิดชอบเป็นป้ายข้อความ ไม่ได้ส่งไปถึงบัญชีบุคคลจริง

## Dataset และผล PMD ที่วัดได้จริง

- ชื่อ: [A Pressure Map Dataset for In-bed Posture Classification v1.0.0](https://physionet.org/content/pmd/1.0.0/)
- ผู้เผยแพร่: PhysioNet; Pouyan et al. (2017), DOI `10.1109/BHI.2017.7897206`; Dataset DOI `10.13026/C2W09K`
- License: Open Data Commons Attribution License v1.0 — ต้องให้เครดิตตามสัญญาอนุญาต
- ใช้เฉพาะ Experiment I: ผู้เข้าร่วม 13 คน อายุ 19–34 ปี, ท่ามาตรฐาน 1–3 รวม 39 ไฟล์ ไม่ใช่ทั้ง 17 ท่า/Experiment II
- ตรวจป้ายกำกับจาก `experiment-info.docx` หน้า 2: 1 = supine, 2 = right, 3 = left; หน้า 1 และ 3 อธิบายผู้เข้าร่วม/รูปแบบข้อมูล
- ค่าที่แสดงเป็น raw sensor counts ไม่ใช่ mmHg และไม่ใช่ระดับความเสี่ยงแผลกดทับ

Protocol:

- แบ่งผู้เข้าร่วมก่อนเทรน: train S1, S3, S4, S7, S8, S10, S12 / validation S2, S6, S13 / test S5, S9, S11
- ใช้ทุกเฟรมที่ 5; ตรวจ shape/finite/nonnegative/nonempty; mean pooling 4×4 ได้ 8×16 แล้ว normalize ด้วยผลรวม
- เก็บได้ train 423, validation 140, test 170 เฟรม; ตัดเฟรมไม่ผ่านคุณภาพ 1 เฟรม
- StandardScaler + LogisticRegression(C=1, balanced) เทียบ RandomForestClassifier(120 trees, max depth 12, min leaf 3, balanced) และ DummyClassifier(most_frequent)
- เลือกจาก validation macro-F1 เท่านั้น; ใช้ cutoff 0.60 ที่กำหนดไว้สำหรับงดรับผล คะแนนโมเดลยังไม่ได้สอบเทียบ

Run ที่ตรวจสอบ: `20261003T064018Z-4fced315`

| วิธี | Validation macro-F1 | Test macro-F1 | Test accuracy ทุกเฟรม |
| --- | ---: | ---: | ---: |
| Logistic Regression (เลือก) | 0.8576 | 0.9708 | 97.06% (165/170) |
| Random Forest | 0.8219 | 0.9650 | 96.47% |
| Majority baseline | 0.1856 | 0.1584 | 31.18% |

หลัง cutoff โมเดลรับผล 167/170 เฟรม (coverage 98.24%), ถูก 164/167 (98.20%) ห้ามใช้เฉพาะตัวเลขหลังงดตอบเพื่ออ้างความแม่นยำทั้งหมด

**ข้อจำกัดสำคัญ:**

- ผลนี้เป็น exploratory: importer รุ่นแรกคัด raw count >1,000 ทิ้งผิดพลาด และได้ตรวจผลรอบแรกก่อนพบปัญหา จึงแก้ตามหลักฐานจาก training subject S1 (พบ raw count ถึง 3,844) ให้เก็บค่าจริงโดยไม่ clip ไม่เปลี่ยน split/โมเดล/hyperparameter/cutoff ต้องมีชุดทดสอบใหม่ก่อนอ้างผล final validation
- Test มีเพียง 3 คน และเฟรมคนเดียวกันสัมพันธ์กัน 170 เฟรมไม่ใช่ 170 ผู้ป่วยอิสระ
- ไม่มีผู้สูงอายุติดเตียงทางคลินิก ไม่มี label แผลกดทับ ไม่มีคลาสเตียงว่าง/ตกเตียง
- แต่ละท่าเป็นการทดลองแยก ไม่ใช่หลักฐานระยะเวลานอนท่าเดิมหรือการพลิกตัวจริง จึงยังไม่คำนวณ alarm “ไม่พลิกตัว” จากชุดนี้
- ไม่มี external validation, calibration หรือผล prospective ที่บ้านจริง ตัวเลขนี้ห้ามอธิบายว่า “แม่นยำดูแลผู้สูงอายุ 97%”

## สถาปัตยกรรมที่ไม่รบกวน monitor

- `evidence_api.py` ใช้โมเดล BIDMC เดิมและอ่านเฉพาะไฟล์ test; ตัดข้อมูลก่อน inference และจำกัด cursor ไม่เกิน +30
- `download_pmd.py` / `train_posture.py` ทำงาน offline ไม่เทรนใน request หรือ telemetry loop
- `posture_api.py` อ่านผล inference ที่บันทึกจากโมเดลจริงไว้ระหว่างเทรน ตรวจ hash ของ report/case ก่อนแสดง ไม่เรียก LLM เดาคำตอบ และไม่มี endpoint อัปโหลด pickle
- `care_api.py` เพิ่มตารางใหม่แบบไม่ลบฐานข้อมูล; ตรวจเวอร์ชันก่อนเปลี่ยนสถานะเพื่อป้องกันผู้ใช้สองหน้าจอเขียนทับกัน
- scheduler ทุก 5 วินาทีสร้างเฉพาะงานถึงกำหนดจากแผน ACTIVE มีงานเปิดได้หนึ่งรอบต่อแผน; รอบถัดไปเริ่มหลังคนบันทึกจบ/ข้าม ไม่สร้างย้อนหลังท่วมคิว
- พักแผนจะยกเลิกงานรอบที่ค้าง เปิดแผนที่พักใหม่จะเริ่มรอบใหม่ทันที แก้รายละเอียดด้วยการพักและสร้างร่างใหม่เพื่อรักษาประวัติ
- authenticated staff-only routes; พอร์ตผู้ป่วยไม่ mount route เหล่านี้ ไม่มี cloud call/Push ภายในสามส่วนใหม่

## ขั้นต่อไปก่อนใช้งานที่บ้านจริง

1. เลือกแผ่นแรงกด/อุปกรณ์ที่มีจริง แล้วสร้าง adapter + ตรวจอายุข้อมูล การหลุด การสอบเทียบ และความต่างจาก PMD ห้ามใช้ค่าข้อมูลสาธิตเป็นค่าคนไข้จริง
2. เก็บข้อมูลกลุ่มเป้าหมายโดยมีความยินยอมและการกำกับดูแล แยกคนและสถานที่ทดสอบ พร้อมผู้เชี่ยวชาญตรวจ label
3. ประเมินรายคน/รายเหตุการณ์ false alarms ต่อวัน เวลาเตือนนำ และการพลาดเหตุการณ์ เทียบ baseline; หลีกเลี่ยง split เฟรมจากคนเดียวกันข้ามชุด
4. เพิ่มบัญชีจริง/สิทธิ์แพทย์พยาบาลญาติ การเข้ารหัส HTTPS นโยบายข้อมูล และ monitoring/backup ก่อน deploy
5. แผนดูแลตามโรคต้องมีบุคลากรกำหนดเฉพาะราย รวมแผนรับมือเมื่อเน็ต ไฟฟ้า เซนเซอร์ หรือ AI ล้มเหลว ระบบนี้ยังไม่ใช่บริการฉุกเฉิน 24 ชั่วโมง
6. Web Push เดิมต้องตั้ง HTTPS/VAPID และทดสอบมือถือจริง รวมกรณี session หมดอายุ/ไม่ได้รับข้อความ การส่งผ่าน provider สำเร็จไม่เท่ากับผู้ดูแลได้รับและรับงาน

## สรุปการสาธิตฟีเจอร์ UX ใหม่ (บุคลากร & ผู้ป่วย)

### ฝั่งบุคลากร (`http://localhost:3000`)

- **เสียงเตือนวิกฤต**: ทดลองสลับปุ่มเปิด/ปิดเสียงแจ้งเตือนเหตุวิกฤตบนหน้ามอนิเตอร์ เพื่อแสดงการแจ้งเตือนเชิงรุกที่ควบคุมการรบกวนในหอผู้ป่วยได้
- **ตัวกรองด่วน**: กดปุ่มกรองสถานะด่วนเพื่อคัดเฉพาะเตียงวิกฤต เฝ้าระวัง หรือมีงานค้างจากทั้งหมด 60 เตียงภายในคลิกเดียว
- **บันทึกด่วน**: เมื่อรับงานหรือบันทึกผลการดูแล ใช้ปุ่มข้อความสำเร็จรูปเพื่อกรอกผลการปฏิบัติงานที่ใช้บ่อยโดยไม่ต้องพิมพ์เองทั้งหมด
- **แม่แบบแผนดูแล**: ในหน้า **แผนดูแล** เลือกใช้แม่แบบแผนดูแลมาตรฐานเพื่อสร้างร่างงานอัตโนมัติ แล้วแสดงขั้นตอนที่บุคลากรตรวจทานก่อนกดเปิดใช้งานจริง
- **การแยกขอบเขตโมเดลใน AI Research Lab**: ชี้ให้ผู้ตรวจประเมินเห็นกล่องอธิบายด้านบนสุดที่แยกชัดเจนระหว่าง **โมเดลเฝ้าระวังสัญญาณชีพสด 1 Hz (PhysioNet BIDMC)** กับ **โมเดลวิจัยย้อนหลัง ICU Sepsis Benchmark**

### ฝั่งผู้ป่วย (`http://localhost:3001`)

- **ปุ่ม `ก+ ตัวอักษรใหญ่`**: กดปุ่ม `ก+ ตัวอักษรใหญ่` บนส่วนหัวของหน้าจอเพื่อขยายขนาดตัวอักษรทันที เหมาะสำหรับผู้สูงอายุและผู้ป่วยข้างเตียง
- **คำอธิบายสัญญาณชีพ**: ชี้ให้ดูคำอธิบายภาษาเข้าใจง่ายใต้ค่าสัญญาณชีพหลัก เพื่อช่วยให้ผู้ป่วยและญาติทราบความหมายของตัวเลขโดยไม่ตื่นตระหนก
- **ปุ่มข้อความด่วน 1-Tap**: ในหมวดติดต่อทีมดูแล ทดลองกดปุ่มข้อความด่วน 1-Tap เพื่อส่งความต้องการหรือแจ้งอาการเบื้องต้นถึงพยาบาลได้ทันทีโดยไม่ต้องพิมพ์เอง
