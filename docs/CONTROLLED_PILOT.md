# การปรับระบบเพื่อทดลองใช้แบบควบคุม

รอบนี้ปรับ workflow และความน่าเชื่อถือของหน้าจอ ยังไม่ใช่การรับรองความแม่นยำทางคลินิก
ทะเบียนยังเป็นข้อมูลสมมติและ replay ยังมาจาก BIDMC ห้ามอ้างว่าเป็นข้อมูลโรคของบุคคลในทะเบียน

## สิ่งที่เปลี่ยน

- เมนูบุคลากรหลัก 5 กลุ่ม พร้อมแถบล่างบนมือถือ และเมนูย่อยในหน้าที่เลือก
- หน้าลำดับการดูแลใช้ `monitor_results` เหมือนหน้ารายละเอียด ไม่ใช้ค่าประวัติเก่ามาแทนค่าปัจจุบัน
- ข้อมูลขาดช่วงถูกจัดว่าต้องตรวจสอบ และผลโมเดลเก่าจะไม่สร้าง anomaly alert ใหม่
- รวมเหตุการณ์ซ้ำตามผู้ป่วยและชนิดสัญญาณ เก็บจำนวนครั้งและเวลาพบล่าสุด
  เหตุการณ์ HR, SpO2 และ model review แยกกัน Agent เสนอเหตุผลหลักตามลำดับกฎต่อรอบ
- ย้าย Alert เดิมเข้ากลุ่มแบบ transaction โดยเก็บแถวเดิมและ snapshot ใน audit
  ไม่ลบประวัติหรืออ้างว่าบุคลากรปิดงานแล้ว รายงานฉบับที่รับรองไปแล้วไม่ถูกแก้ย้อนหลัง
- ค่ากลับพ้นเกณฑ์เดิมแสดงเวลาที่พบ แต่ไม่ปิดงานเอง และข้อมูลขาดช่วงไม่ถือว่าฟื้นตัว
- ก่อนส่งต่อหรือปิดต้องเขียนบันทึก ผู้รับผิดชอบมาจาก session และตรวจ version กันการแก้ทับ
- รายการ Alert แบ่งหน้า 20 รายการ กรอง ID/โซน/สถานะก่อนตัดหน้า
- ผู้ป่วยแจ้งเรื่องและติดตามคำตอบได้ ฝั่งบุคลากรรับเรื่องและตอบโดยมี audit
  ช่องทางนี้ไม่ใช่ช่องทางฉุกเฉินและยังไม่มี Web Push สำหรับข้อความผู้ป่วย
- ส่งข้อความซ้ำด้วย request key เดิมไม่สร้างซ้ำ จำกัด 5 รายการ/ผู้ป่วย/ชั่วโมง
- หน้าแนวโน้มผู้ป่วยเริ่มที่ 1 ชั่วโมง เมื่อโหลดค่าปัจจุบันสะดุดยังคงหน้าเดิมพร้อมป้ายแจ้งปัญหา
- มีบัญชีรายบุคคล เก็บรหัสผ่านแบบ salted scrypt รีเซ็ตรหัสผ่านแล้วเพิกถอน session เก่า

## เปิดระบบด้วย production bundles

จาก root โปรเจกต์:

```bash
npm --prefix frontend run build
npm --prefix frontend run build:patient
.venv/bin/python scripts/run_ward.py --production
```

ใช้ `--restart --production` เมื่อต้องการเริ่มใหม่ Launcher ใช้พอร์ตเดิม
3000/3001 และ 8000/8001 และต้องมี terminal เปิดไว้ ยังไม่ใช่บริการที่รับประกัน 24 ชั่วโมง
หลังแก้ frontend ต้อง build ทั้งสองชุดใหม่ก่อนใช้ production mode

## ตั้งบัญชีรายบุคคล

ให้ CLI กับ Backend ใช้ `WARD_DB_PATH` แบบ absolute เดียวกัน
ค่าเริ่มต้น launcher และ CLI คือ `backend/runtime/ward-demo.db`

```bash
.venv/bin/python scripts/manage_account.py staff nurse.one
.venv/bin/python scripts/manage_account.py staff doctor.one
.venv/bin/python scripts/manage_account.py patient A001
```

ระบบถามรหัสผ่านแบบไม่แสดงบนหน้าจอ อย่างน้อย 12 ตัวอักษร
ตั้ง `WARD_DEMO_ID_LOGIN=0` ใน environment/backend .env และ restart หลังสร้างบัญชีแล้ว
เมื่อปิดโหมดนี้ บัญชี clinician แบบรหัสร่วมและผู้ป่วยที่กรอก ID อย่างเดียวจะเข้าไม่ได้
บัญชีผู้ป่วยที่ตั้งรหัสผ่านแล้วต้องใช้รหัสนั้นเสมอแม้ยังเปิดโหมดสาธิต
แพทย์กับพยาบาลมีสิทธิ์บุคลากรเหมือนกันในรุ่นนี้ ยังไม่ได้แยกสิทธิ์สั่งการรักษาหรือ delegate ญาติหลายบัญชี

## สำรองและทดสอบคืนข้อมูล

```bash
.venv/bin/python scripts/backup_ward.py /absolute/path/ward-demo.db /absolute/path/new-backup.db
```

ใช้ SQLite backup API จึงรองรับฐานข้อมูลที่เปิด WAL อยู่ ไม่เขียนทับไฟล์เดิม
ตรวจ integrity ก่อนแจ้งสำเร็จ ไฟล์ backup มี session และข้อมูลสุขภาพ ต้องเก็บในที่จำกัดสิทธิ์
ทดสอบ restore ในฐานข้อมูลแยกก่อน หยุดทุก writer ก่อนเปลี่ยนฐานข้อมูลจริง
ยังไม่มีการตั้ง schedule หรือ off-site backup ให้อัตโนมัติ

## ขอบเขตที่ยังต้องทำก่อนใช้งานกับผู้ป่วยจริง

ต้องเชื่อมอุปกรณ์จริงที่ผ่านการตรวจคุณภาพ ทดสอบโมเดลกับกลุ่มเป้าหมาย
และกำหนดผู้รับผิดชอบ alert/การส่งต่อร่วมกับทีมคลินิกก่อน ไม่มีการเพิ่มความแม่นยำของโมเดลโดยอาศัยการปรับ UI
ส่วนการ deploy ต้องมี HTTPS, secure cookies, named accounts, การแยกสิทธิ์ผู้ดูแล/บุคลากร/ญาติ,
service supervision, logging/monitoring ภายนอก, backup/restore ที่ทดสอบแล้ว และแผนเมื่อเน็ตหรือไฟดับ
Web Push ต้องตั้ง VAPID, สมัครบนโทรศัพท์ และทดสอบการรับจริง; provider acceptance ไม่ยืนยันว่าเจ้าหน้าที่อ่านแล้ว
หน้าสถานะระบบช่วยเห็นการตั้งค่าที่ค้างอยู่ แต่ไม่ใช่ใบรับรองความพร้อมทางการแพทย์

## เส้นทางทดสอบสั้น

1. บุคลากร → ภาพรวม → งานดูแล → รายการแจ้งเตือน → เปิดผู้ป่วย → เปิดเหตุการณ์ของรายนั้น
2. รับผิดชอบ → กรอกผลตรวจสอบ → ปิดงาน ตรวจผู้ดำเนินการใน audit
3. ผู้ป่วย A001 → แผนดูแล → แจ้งเรื่อง → บุคลากร งานดูแล/ลำดับการดูแล → ข้อความจากผู้ป่วย
4. บุคลากรรับเรื่องและตอบ → ผู้ป่วยเห็นสถานะและข้อความที่ตอบ โดยไม่เห็นบันทึกภายในหรือผู้ป่วยอื่น
5. หยุดแหล่งข้อมูล → ค่าหายไปจากสถานะปัจจุบันและงด forecast; งานที่เปิดอยู่ยังไม่ถูกปิด
